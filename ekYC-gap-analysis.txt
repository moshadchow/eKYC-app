  Gap 1 — KYC Lifecycle UI (API ready, zero UI)

  AppRouter.tsx line 55 — literally a placeholder div:
  <Route path="/admin/lifecycle" element={
    <div className="p-6 text-surface-500">KYC Lifecycle — coming in next step</div>
  } />
  Backend APIs are fully implemented (/lifecycle/accounts/{id}/refresh-schedule, /refresh/initiate, /refresh/complete,
  /accounts/overdue). Needs a full dashboard page.

  ---
  Gap 2 — Fingerprint Verification (no frontend at all)

  Backend endpoint /kyc/applications/{app_id}/verify/fingerprint and CRUD exist. onboardingStore has no fingerprint step.
  The OnboardingPage.tsx flow goes nid_capture → face_match → profile — fingerprint is never surfaced to the user for
  assisted onboarding channel.

  ---
  Gap 3 — Face Selfie Not Actually Uploaded

  OnboardingPage.tsx line ~186 has this comment:
  // For dev: use a placeholder storage key
  The selfie capture works in the UI but the image is never sent to storage — a fake storage_key is passed to the backend.
  The document upload endpoint exists and works; it just isn't wired to the face capture step.

  ---
  Gap 4 — Risk Scoring: Profession & Business Activity Hardcoded

  crud_compliance.py hardcodes:
  score_business_activity: 3
  score_profession: 3
  BFIU Annexure-1 requires a lookup table — e.g. Jeweler/Money Changer/Real Estate → 5, IT Employee/Lawyer → 4, Salaried →
  1. Without this, high-risk profiles get underscored and may bypass EDD. The CustomerProfile model already stores
  profession and source_of_fund — the data exists, the scoring logic just isn't written.

  ---
  Gap 5 — Notification Delivery (records written, nothing sent)

  Account activation creates a notifications table row. No SMS or email gateway is wired. There is no background worker or
  scheduled task sending those records. For onboarding completion the customer receives no confirmation.

  ---
  Gap 6 — Compliance Page Navigation

  CompliancePage.tsx has no back button to return to the agent queue. After submitting a decision the agent has to manually   navigate. Minor UX gap.

  ---
  Gap 7 — No Document Viewer

  Uploaded documents (NID front/back, selfie, signature) are stored with a storage_key but there is no UI anywhere to
  render or preview them — neither in the compliance review page nor in the admin approval summary.

  ---
  Gap 8 — Audit Page: No Entity Drill-down

  AuditPage.tsx lists logs but there is no detail view / entity-specific trail. The backend supports GET
  /audit/entities/{entity_type}/{entity_id} — it's just not wired in the frontend.
